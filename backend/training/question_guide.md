# 면접 질문 작성 기준 (질문 전용 파인튜닝 데이터 · v1, 2026-10-06)

질문 전용 어댑터(Bllossom-3B LoRA)의 학습 데이터를 만들 때 1차 작성(Claude)과 2차 검토(팀)가 같은 기준을 쓰기 위한 문서.
채점 기준표(`claude_rubric_v3.md`)와 같은 역할.

## 1. 자기소개서 질문 (면접 시작 전 질문 풀)

입력: 지원 회사 · 지원 직무 · 직무 설명(직무 수행 업무) · 인재상(선택) · 자기소개서(선택)
출력: 질문 6개 JSON 배열 — 순서는 `자기소개서, 자기소개서, 직무, 자기소개서, 자기소개서, 직무`
(서버가 면접마다 3개씩 꺼내 쓰므로 면접 한 번 = 자기소개서 질문 2 + 직무 질문 1)

자기소개서가 비어 있으면 6개 모두 직무 질문. 자기소개서 경험이 2개 이하이면 같은 경험을 다른 각도로 묻는다.

### 좋은 질문의 조건
1. **근거**: 자기소개서에 실제로 쓴 경험 · 수치 · 판단을 짚는다. 없는 내용을 지어내지 않는다.
2. **한 번에 하나**: 한 문장, 질문 하나 (40~120자). "~와 ~, 그리고 ~는?"처럼 여러 개를 묶지 않는다.
3. **파고드는 각도**: 자기소개서에 *빠진 것*을 묻는다 — 쓰여 있는 걸 그대로 다시 말하게 하지 않는다.
   - 본인 역할 · 직접 한 행동 (특히 "팀이 ~했다"처럼 주어가 흐릴 때)
   - 판단 근거 (왜 그 방법을, 다른 선택지는)
   - 결과 확인 방법 (수치를 썼다면 어떻게 측정했는지, 없다면 무엇으로 확인했는지)
   - 어려움 · 실패 · 갈등과 대처
   - 배운 점을 이 직무에서 어떻게 쓸지
   - 한 질문 풀 안에서 각도가 겹치지 않게 섞는다.
4. **구체적인 말 사용**: 자기소개서의 고유한 말(프로젝트명 · 기술 · 상황)을 넣어, 다른 지원자에게는 할 수 없는 질문이 되게.
5. **자연스러운 면접관 말투**: 존댓말, "~말씀해 주세요." / "~무엇이었나요?" / "~어떻게 하셨나요?"
   - 자기소개서 문장을 길게 인용하지 않는다 (핵심 구절만).
   - 답을 암시하거나 칭찬 · 평가를 섞지 않는다 ("훌륭한 경험인데요" ✗).
6. **포부 · 지원 동기 문장은 질문 거리로 쓰지 않는다** (자기소개 · 지원동기는 고정 질문이 따로 있다).
   단, 포부와 경험을 잇는 질문은 직무 질문에서 가능.

### 직무 질문
- 직무 설명의 업무 항목을 지원자의 배경(자기소개서 경험 · 전공)과 잇는다.
  예) "자기소개서의 FPGA 타이밍 문제 해결 경험을 메모리 컨트롤러 설계에 적용한다면 무엇부터 확인하시겠어요?"
- 지식 확인은 직무 수준에 맞게 하나만 ("~의 차이를 설명해 주세요" 정도). 시험 문제처럼 길게 내지 않는다.
- 인재상은 직무 질문 하나 정도에 자연스럽게 녹인다 (인재상 단어를 그대로 읊게 하지 않는다).

### 나쁜 예
- "자기소개서에 대해 말씀해 주세요." (근거 · 각도 없음)
- "협업 경험이 있나요?" (예/아니오, 자기소개서와 무관)
- "Redis 캐시를 도입해 응답 시간을 3초에서 0.2초로 줄였다고 하셨는데, 그 경험을 말씀해 주세요." (쓰인 걸 다시 말하게 함)
- "프로젝트에서 맡은 역할과 어려웠던 점, 그리고 배운 점을 말씀해 주세요." (질문 3개)

## 2. 꼬리 질문 (답변 직후)

입력: 방금 한 질문 · 지원자 답변 (+ 이 면접의 다른 질문 목록)
출력: 꼬리 질문 1개 (문장 하나)

- 답변에 **나온 말**을 짚고, 답변에 **빠진 것**을 묻는다: 흐린 주어("저희가"), 근거 없는 주장, 결과 없는 행동, 설명 없는 판단.
- 이 면접의 다른 질문이 이미 다루는 경험 · 각도는 피한다.
- 답변이 음성 인식이라 오타가 있을 수 있다 — 오타 단어를 그대로 인용하지 말고 뜻을 살려 쓴다 ("클럽" → "클럭").
- 지원 동기 답변: 경험이 아니라 관심의 계기이므로 "그 관심을 위해 실제로 해 본 것"을 묻는다.
- 답변이 매우 추상적이면 구체적인 사례 하나를 요청한다.
- 압박 · 비꼬기 · 평가 ✗. 짧게(30~100자).
